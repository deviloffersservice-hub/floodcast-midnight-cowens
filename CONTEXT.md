# Project context: FLOODCAST (Team Midnight Cowens)

Hand-over notes for anyone (person or AI assistant) picking up this repo. They cover what the
project is, which rules bind it, what has been decided and why, the current state, and what must
not be changed.

- To set the project up on the Windows laptop, follow [`CLAUDE.md`](CLAUDE.md).
- For users, see [`README.md`](README.md).
- For the model details and evidence, see [`model_card.md`](model_card.md).

## 1. The task

FLOODCAST is a 24-hour hackathon, the November 2026 regression challenge in "Disaster Risk & Early
Warning Systems".

- **Predict** daily river discharge `discharge_cfs` (cubic feet per second) for each
  `(station_id, date)` in `test.csv`.
- **Inputs:** daily precipitation, max/min temperature, soil moisture, and 4 static catchment
  attributes:
  - drainage area (sq mi);
  - mean elevation (ft);
  - slope (%);
  - forest cover (%).
- **No past discharge** is in `test.csv`. The river's "memory" must come from weather history.

The judges run every team's model on their own hidden test CSV, and **the most accurate model
wins**. The brief stresses that models must work on stations **not seen in training**. The team
expects the judges' file to be a mix of known and new rivers.

## 2. Rules from the problem statement (FLOODCAST_Participant_PS_Updated.pdf)

**Scoring.** Each metric is min-max normalised to 0–100 across all teams, then combined with these
weights:

| Metric | Weight |
|---|---|
| RMSE (all rows) | 40% |
| RMSE on each station's top-10% discharge days | 30% |
| MAE | 20% |
| R² | 10% |

During the event, the live leaderboard uses raw RMSE only.

**predictions.csv must:**
- have exactly the columns `station_id,date,discharge_cfs`, in that order;
- have one row per test row, with no missing or extra rows;
- contain only non-negative floats, with no NaN;
- be UTF-8.

`floodcast/schema.py:validate_submission` enforces all of this before any file is written.

**Team validation rules** (added 2026-11-05; details in README "Input / output contract"): reject
unknown catchment IDs (= not in test.csv; never-seen rivers stay valid), unexpected dates, NaN,
infinity, invalid probabilities and malformed records; non-negative discharge (clipping at 0 is the
documented transformation); ordered intervals with a coverage field; one prediction per key, so a
test.csv that repeats a key is rejected; missing keys are listed and the file is rejected.

**Disqualified:**
- negative values;
- missing rows;
- submitting the test labels;
- a predictions.csv not generated by running our code.

Using test discharge as input is leakage.

**Allowed:**
- any ML framework;
- declared pre-trained models;
- adding USGS stations;
- any feature engineering;
- teams of 1–4.

**Not allowed:**
- hand-editing predictions;
- a model built before the event;
- sharing with other teams.

## 3. Decisions already taken (do not reopen without the team)

| Decision | Why |
|---|---|
| US data only (USGS + Open-Meteo + GAGES-II); the Indian CWC/IMD files in the parent folder are **not** used | Follow the PDFs. Their USGS links failed only because of stray `;` characters (`&sites;=`). The cleaned URLs work |
| CPU-only LightGBM, deterministic (seed 42, 4 threads) | Must run on a Windows i5 laptop with 8 GB RAM and no GPU |
| Final model retrained on **all** labelled days 2012-01-01 → 2025-10-31 | Team decision on 2026-11-05, to maximise accuracy on the judges' file. Honest out-of-sample numbers come from the evaluation model, which was trained on 2012–2022 only |
| Separate model for never-seen rivers, plus a ×1.25 median-to-mean correction | The brief requires generalisation to new stations. Chosen on 2 time folds × station-group CV |
| Cold-start fill (`FRONT_DAYS = 60`) | A judge's test.csv has no earlier weather. This fills the missing rain history at the file start |
| 10 extra GAGES-II stations **not** used in the final model | New-station CV got slightly worse in both folds. Kept as opt-in (`scripts/add_stations.py`, `build_dataset.py --with-extra`) |
| Product layer for two users: a riverside resident and a district disaster officer, in English, Hindi and Kannada | Stand-out on user point of view. Accuracy still decides the winner |
| Local app (Gradio), no hosting | Runs on the laptop. Offline replay plus a saved-forecast fallback mean the demo survives a network failure |
| Also deployed online (2026-11-05): `server.py` serves the HTML/CSS app at `/` and the Gradio app at `/gradio/`, on Render's free plan from `Dockerfile` + `render.yaml` (Hugging Face needs PRO for CPU hardware; free accounts only get ZeroGPU) | Team request. The laptop version stays the offline backup for the demo |

## 4. Data

| Source | What | Notes |
|---|---|---|
| USGS NWIS daily values, param 00060 | Discharge (cfs) | Ice- or equipment-affected days and no-data codes are dropped. Missing targets are never filled |
| Open-Meteo archive at each gauge | Precipitation, Tmax, Tmin, soil moisture 0–7 cm (m³/m³) | Free tier: 600 calls/min, 5,000/hour, 10,000/day. A 14-year station costs about 147 |
| USGS GAGES-II | Drainage area, elevation, slope, forest cover | The StreamStats API was offline |
| Open-Meteo forecast API | 16-day forecast for the live app | Cached 3 h. Offline snapshot in `data/snapshot/` |

The data covers **49 training stations**; the app lists 53 gauges.

| Split | Dates | Station-days |
|---|---|---|
| Evaluation train | 2012–2022 | 193,438 |
| Held-out test | 2023-01-01 → 2025-10-31 | 49,361 |
| Final model | All labelled days | 242,799 |

Files: `data/processed/` (train.csv, test.csv, test_labels.csv, train_all.csv, warm-up parquet
files, station metadata).

## 5. Model (`solution.py`, `floodcast/`)

- **Features** (`floodcast/features.py`):
  - rolling rain sums over 3–90 days, rain lags, an antecedent-precipitation index;
  - soil-moisture means and trend;
  - a snow and melt proxy, season;
  - static attributes.
  - Known stations also get the station's own flow statistics.
- **Known stations:** an average of 3 LightGBM members (`KNOWN_MEMBERS` in `solution.py`):
  - log(1+Q), 1550 rounds, 31 leaves, min 20 per leaf, feature fraction 0.6;
  - log flow per sq mi, 447 rounds;
  - Tweedie, 1320 rounds.
- **New stations:** a model of log flow per sq mi (330 rounds, 127 leaves, min 200 per leaf,
  feature fraction 0.6), scaled by drainage area, ×1.25.
- **Optional history:** `--train` at prediction time warms up the rain windows and gives
  climatology for new stations. Test discharge is never read.
- **Product extras:**
  - risk levels per river: top-10% day, 2-, 5- and 20-year flood (Gumbel), measured on the model's
    own climate;
  - a split-conformal "likely range";
  - SHAP "why" drivers;
  - a what-if rainfall slider;
  - WhatsApp text and CAP 1.2 XML alerts.

## 6. Accuracy (all in raw cfs)

**Evaluation model** (trained 2012–2022, scored on the 2023-01 → 2025-10 holdout):

| | RMSE | RMSE top-10% | MAE | R² |
|---|---|---|---|---|
| Baseline: station monthly mean | 45,913 | 50,655 | 12,116 | 0.815 |
| Known stations | 38,807 | 55,561 | 8,914 | 0.867 |
| New stations (station-group CV) | 54,290 | 116,158 | 15,087 | 0.741 |

**Fine-tuning** used validation files that start cold, like a judge's file:
- **New stations:** R² 0.73–0.75 → 0.78–0.82; flood-peak RMSE −17% to −29%.
- **Known stations:** better on 2020–22, mixed on 2023–25.

Full table: `model_card.md`.

`predictions.csv` is the final model's output on our own `data/processed/test.csv`
(2023-01 → 2025-10), so it is in-sample for that model. Quote the evaluation-model numbers above
as the honest score.

**Practice kit** (`judge_test/`): files in the organisers' format with an answer key; see the README
section. `scripts/verify_install.py` prints its score.
Kit 2025-11-01 → 2026-10-31, `test.csv`, all 7 rivers: RMSE 24,232 | RMSE top-10% 43,028 | MAE 7,701 | R² 0.903.

## 8. How correctness is checked

- `pytest -q tests`: **120 tests** covering:
  - messy inputs and the validation rules;
  - risk levels;
  - all 3 languages;
  - alerts;
  - forecast fallback;
  - the app handlers;
  - practice-kit scoring;
  - the Batch tab's evaluation metrics (8 families).
- `python scripts/verify_install.py`: re-predicts the holdout and compares it with the committed
  `predictions.csv` (byte-identical on the Mac, within tolerance on other CPUs), then scores the
  practice kit.
- A clean-room fresh clone plus a fresh venv has reproduced `predictions.csv` byte-identically on
  the Mac.
- The UI was audited at 7 laptop sizes (1280×600 to 1920×1080) × 2 themes × 3 languages × 4 tabs:
  - no text under 12 px;
  - no overlap or clipping;
  - WCAG AA contrast.

## 9. Do not change

- `models/`, `predictions.csv`, `data/processed/` and `judge_test/`, unless the team decides to
  retrain on the Mac.
- `requirements.txt` pins: Python 3.12, chosen so that every package has a Windows wheel.
- Model hyperparameters, `UNSEEN_SCALE` and `FRONT_DAYS`. These were chosen by validation; changes
  need the same 2-fold evidence.
- Never hand-edit predictions. Never feed test discharge to the model.
