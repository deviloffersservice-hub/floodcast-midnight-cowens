# Instructions for Claude Code: set up and run FLOODCAST on the team's Windows laptop

This file is for a Claude Code session on the team's **Windows laptop**: a Dell Inspiron 3310 with
an i5 13th gen CPU, 8 GB RAM and no GPU. The user will paste the GitHub link and ask you to clone
and run the project. Follow the steps below in order.

Background on the project, the rules and the decisions already taken is in
[`CONTEXT.md`](CONTEXT.md). Read it before you change anything.

On the training Mac (macOS), skip the setup steps. The **Rules** section still applies.

Repository: <https://github.com/deviloffersservice-hub/floodcast-midnight-cowens>

---

## Rules (read first)

1. **Do not assume. Ask the user** when something is unclear, fails in an unexpected way, or needs a
   choice. Show the exact error text.
2. **Do not retrain or change the model.** Do not run any of these: `solution.py train`,
   `scripts/build_dataset.py`, `scripts/fetch_data.py`, `scripts/add_stations.py`,
   `scripts/make_judge_kit.py`, `scripts/compute_thresholds.py`, `scripts/evaluate*.py`,
   `scripts/make_snapshot.py`, `scripts/make_slides.py`. They download data or overwrite committed
   results. The model is trained on the Mac.
3. **Do not edit** `models/`, `data/`, `judge_test/`, `reports/` or `predictions.csv`. Never edit
   predictions by hand. The hackathon disqualifies a predictions.csv "not generated by running your
   code".
4. **Never use the discharge values of a test file as input.** Only `answers.csv`-style files are
   used, and only for scoring after prediction.
5. **Do not commit or push** unless the user explicitly asks. If they do, run `git pull --rebase`
   first, because the Mac pushes to the same repo.
6. **Do not change the Python version or the package versions.** Use Python **3.12 (64-bit)** and
   exactly `requirements.txt`. The pins match Windows wheels, so nothing needs compiling.
7. **If a test fails, report it. Do not "fix" code** to make it pass without asking.
8. **Admin prompts are the user's.** If Windows shows an admin (UAC) prompt, tell the user to click
   **Yes**. You cannot click it.

## Shell notes

Claude Code on Windows runs commands in **Git Bash**. Use forward slashes and call the venv's Python
directly: `.venv/Scripts/python.exe`. Do not use `activate`.

The `.bat` files (`setup.bat`, `run_app.bat`, `predict.bat`) are for people who double-click them.
They end with `pause`, which waits for a key press and would hang your shell. Use the commands below
instead.

In PowerShell, the same commands look like this:

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests
```

## Step 1: Clone

Clone into the home folder, not inside OneDrive (OneDrive locks and syncs the large `.venv`):

```bash
cd ~
git clone https://github.com/deviloffersservice-hub/floodcast-midnight-cowens.git
cd floodcast-midnight-cowens
```

If the folder already exists, do not delete it. Run `git status`. If there are no local changes,
run `git pull`.

If git is missing, ask the user to download the ZIP instead (green **Code** button →
**Download ZIP**) and unzip it to `C:\Users\<name>\floodcast-midnight-cowens`.

## Step 2: Python 3.12 (64-bit)

Check whether it is already installed:

```bash
py -3.12 -c "import sys, struct; print(sys.version, struct.calcsize('P') * 8, 'bit')"
```

If that fails, check the default user install path:

```bash
"$LOCALAPPDATA/Programs/Python/Python312/python.exe" --version
```

If neither works, install it with the official python.org build. It needs internet and installs
for the user only:

```bash
winget install -e --id Python.Python.3.12 --scope user --accept-package-agreements --accept-source-agreements
```

Then use the full path, because the current shell does not see the new PATH yet:

```bash
PY="$LOCALAPPDATA/Programs/Python/Python312/python.exe"
"$PY" --version
```

If you found Python with `py -3.12`, set `PY` to the path it printed instead:

```bash
PY="$(py -3.12 -c 'import sys; print(sys.executable)')"
```

If winget is missing or fails, stop and ask the user to install it from
<https://www.python.org/downloads/windows/>. They should pick the Windows installer (64-bit) for
the latest 3.12.x and tick **Add python.exe to PATH**.

## Step 3: Microsoft C++ runtime (LightGBM needs it)

Check for the runtime files:

```bash
ls /c/Windows/System32/vcomp140.dll /c/Windows/System32/msvcp140.dll
```

If either file is missing, install the runtime. First tell the user to click **Yes** on the admin
prompt:

```bash
winget install -e --id Microsoft.VCRedist.2015+.x64 --accept-package-agreements --accept-source-agreements
```

If winget is not available, ask the user to run <https://aka.ms/vs/17/release/vc_redist.x64.exe>.

## Step 4: Virtual environment and packages

This needs internet and takes a few minutes. Make sure there are at least 2 GB free on the disk.
Give the commands a 10-minute timeout.

```bash
"$PY" -m venv .venv
.venv/Scripts/python.exe -m pip install --disable-pip-version-check --upgrade pip
.venv/Scripts/python.exe -m pip install --disable-pip-version-check -r requirements.txt
```

If pip starts *building* a package from source, or says "no matching distribution", the Python is
the wrong version or 32-bit. Go back to Step 2.

## Step 5: Self-tests

```bash
.venv/Scripts/python.exe -m pytest -q tests
```

Expected result: **`76 passed`**, 0 failed. It takes about 6 s on the Mac, so expect well under a
minute on the laptop.

## Step 6: Install check (model reproduces + practice kit score)

```bash
.venv/Scripts/python.exe scripts/verify_install.py
```

Expected: both lines `PASS`, then `ALL CHECKS PASSED`, exit code 0.

- **[1/2] Reproduction.** On Windows the check may say *"within tolerance (not byte-identical)"*.
  That is still a pass. An Intel CPU can round a few last digits differently from the Mac's Apple
  CPU.
- **[2/2] Practice kit.** This line prints the accuracy on `judge_test/`. Copy the numbers into
  your report.

## Step 7: Start the web app

Run it in the **background** (it keeps running), from the repo folder:

```bash
.venv/Scripts/python.exe app.py
```

It opens the browser at <http://127.0.0.1:7860> by itself. To confirm it is up:

```bash
curl --retry 30 --retry-delay 2 --retry-connrefused -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7860/
```

Expected output: `200`.

If port 7860 is busy, use another port:

```bash
.venv/Scripts/python.exe -c "import app; app.launch_app(7870)"
```

The user can also just double-click `run_app.bat`. To stop the app, stop that background task, or
close the `run_app.bat` window.

## Step 8: Report back to the user

Keep the report short:

- the Python version;
- the pytest result line;
- the two lines from `verify_install.py`, including the practice-kit scores;
- the app URL;
- anything that needed the user (admin prompt, manual install) or that failed. For failures, give
  the exact error.

Then tell the user how to use the app:

- The language picker is at the top (English / हिन्दी / ಕನ್ನಡ).
- **Am I safe?** is the resident view. **Officer dashboard** has the map, the ranked rivers, the
  hydrograph, the why, the what-if and the CAP alert.
- **Batch** takes `test.csv` and returns `predictions.csv`, and gives a score if `answers.csv` is
  uploaded.
- **Manual input** predicts a single day.
- Without internet, the live forecast falls back to a saved forecast, and **Replay a past flood**
  works fully offline.

## Judging: the organizers hand over a CSV

The judges run each team's model on their own `test.csv`, and the most accurate model wins. When the
user gives you their file:

```bash
.venv/Scripts/python.exe solution.py predict --test "PATH/TO/test.csv" --out "PATH/TO/predictions.csv"
```

If the judges also give a training/history file with past discharge, add `--train "PATH/TO/train.csv"`.
Its weather warms up the rainfall windows, and its discharge gives climatology for rivers the model
has never seen.

Output and validation:

- `predict` checks every rejection rule from the brief before writing: exact columns
  `station_id,date,discharge_cfs`, one row per test row, no NaN, no negatives.
- If it raises an error, show it to the user. Do not work around it.
- Excel quirks are handled automatically: dropped leading zeros, dd/mm/yyyy dates, soil moisture
  in %, semicolons, BOM, Windows-1252.
- If the judges also give the true values, upload `test.csv` + `answers.csv` in the app's **Batch**
  tab to see RMSE, top-10% RMSE, MAE and R².
- **Ask the user** before copying a judges' `predictions.csv` into the repo or pushing it.
- Double-clicking alternative for the user: drag `test.csv` onto `predict.bat`. It writes
  `predictions.csv` next to `test.csv`.

A 200,000-row file takes about 6 s and about 0.7 GB of RAM, so 8 GB is plenty.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `DLL load failed` / `vcomp140.dll` when importing lightgbm | Step 3 (C++ runtime), then rerun the tests |
| pip builds from source / "no matching distribution" | Wrong Python: must be 3.12 64-bit (Step 2). Delete `.venv` only after asking, then redo Step 4 |
| "running scripts is disabled on this system" | PowerShell blocked `Activate.ps1`. Don't activate; call `.venv/Scripts/python.exe` directly |
| `pytest` command not found | Use `.venv/Scripts/python.exe -m pytest` |
| Port 7860 already in use | `.venv/Scripts/python.exe -c "import app; app.launch_app(7870)"` |
| pip install very slow | Windows Defender scans every file. Wait; don't cancel |
| Live forecast says offline / snapshot | No internet or Open-Meteo is down. Expected fallback; Replay works offline |
| `verify_install.py` reproduction FAIL (not just "within tolerance") | Stop and report the printed numbers to the user. Do not regenerate `predictions.csv` |
| Files open in OneDrive / sync errors | Re-clone to `~/floodcast-midnight-cowens` (outside OneDrive) |
