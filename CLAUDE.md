# Instructions for Claude Code: set up and run FLOODCAST on the team's Windows laptop

This file is for a Claude Code session on the team's **Windows laptop**: a Dell Inspiron 3310 with
an i5 13th gen CPU, 8 GB RAM and no GPU. The user will paste the GitHub link and ask you to clone
and run the project. Do two tasks, in order:

- **Task 1 (Steps 1–8):** install everything, test it, and start the app.
- **Task 2:** build the fresh practice kit (Nov 2025 → Oct 2026), score the model on it, update the
  docs, and push.

**Work on your own.** When something fails, find the cause and fix it, then continue. Only stop for
the user when you need one of these:
- a login;
- an admin (UAC) click;
- a decision that is theirs to make.

Background on the project, the rules and the decisions already taken is in
[`CONTEXT.md`](CONTEXT.md). Read it before you change anything.

On the training Mac (macOS), skip the setup steps. The **Rules** section still applies.

Repository: <https://github.com/deviloffersservice-hub/floodcast-midnight-cowens>

---

## Rules (read first)

1. **Fix errors yourself.** Environment problems are yours to fix: installs, PATH, permissions,
   encodings, busy ports, network retries.
   - If a bug in the code blocks a step, make the smallest fix that solves it, then rerun the
     **full** test suite.
   - Never make a test pass by weakening the test.
   - List every fix in your final report and in the commit message.
2. **Ask the user only for:**
   - a login (GitHub sign-in);
   - an admin (UAC) prompt (tell them to click **Yes**; you cannot click it);
   - a git name/email if none is set;
   - a real decision.

   Show the exact error text when you ask. Do not guess facts.
3. **Never change the model or its outputs.**
   - Do not run `solution.py train`, and do not edit `models/` or `predictions.csv`.
   - Do not change hyperparameters, `UNSEEN_SCALE` or `FRONT_DAYS`.
   - Do not run the data-building scripts: `scripts/build_dataset.py`, `fetch_data.py`,
     `add_stations.py`, `compute_thresholds.py`, `evaluate*.py`, `make_snapshot.py`,
     `make_slides.py`. The model is trained on the Mac.
   - The only scripts you run are `scripts/verify_install.py`, `scripts/make_judge_kit.py`
     (Task 2) and `scripts/score_kit.py`.
4. **Never edit predictions by hand, and never use a test file's discharge as input.** The
   hackathon disqualifies a predictions.csv "not generated by running your code". Answer files are
   only for scoring after prediction.
5. **Python 3.12 (64-bit) with exactly `requirements.txt`.** The pins match Windows wheels, so
   nothing needs compiling. Do not upgrade or swap packages.
6. **Git:**
   - Commit and push only the Task 2 results, plus any fix you had to make.
   - Run `git pull --rebase` before pushing. Never force-push.
   - If the user asks for anything else to be pushed, do that too.

## Shell notes

Claude Code on Windows runs commands in **Git Bash**. Use forward slashes and call the venv's Python
directly: `.venv/Scripts/python.exe`. Do not use `activate`.

The `.bat` files (`setup.bat`, `run_app.bat`, `predict.bat`) are for people who double-click them.
They end with `pause`, which waits for a key press and would hang your shell. Use the commands below
instead.

In PowerShell, the same commands look like this:

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests
```

## Step 1: Clone

Clone into the home folder, not inside OneDrive (OneDrive locks and syncs the large `.venv`):

```bash
cd ~
git clone https://github.com/deviloffersservice-hub/floodcast-midnight-cowens.git
cd floodcast-midnight-cowens
```

If the folder already exists, do not delete it. Run `git status`. If there are no local changes,
run `git pull`.

If git is missing, ask the user to download the ZIP instead (green **Code** button →
**Download ZIP**) and unzip it to `C:\Users\<name>\floodcast-midnight-cowens`.

## Step 2: Python 3.12 (64-bit)

Check whether it is already installed:

```bash
py -3.12 -c "import sys, struct; print(sys.version, struct.calcsize('P') * 8, 'bit')"
```

If that fails, check the default user install path:

```bash
"$LOCALAPPDATA/Programs/Python/Python312/python.exe" --version
```

If neither works, install it with the official python.org build. It needs internet and installs
for the user only:

```bash
winget install -e --id Python.Python.3.12 --scope user --accept-package-agreements --accept-source-agreements
```

Then use the full path, because the current shell does not see the new PATH yet:

```bash
PY="$LOCALAPPDATA/Programs/Python/Python312/python.exe"
"$PY" --version
```

If you found Python with `py -3.12`, set `PY` to the path it printed instead:

```bash
PY="$(py -3.12 -c 'import sys; print(sys.executable)')"
```

If winget is missing or fails, stop and ask the user to install it from
<https://www.python.org/downloads/windows/>. They should pick the Windows installer (64-bit) for
the latest 3.12.x and tick **Add python.exe to PATH**.

## Step 3: Microsoft C++ runtime (LightGBM needs it)

Check for the runtime files:

```bash
ls /c/Windows/System32/vcomp140.dll /c/Windows/System32/msvcp140.dll
```

If either file is missing, install the runtime. First tell the user to click **Yes** on the admin
prompt:

```bash
winget install -e --id Microsoft.VCRedist.2015+.x64 --accept-package-agreements --accept-source-agreements
```

If winget is not available, ask the user to run <https://aka.ms/vs/17/release/vc_redist.x64.exe>.

## Step 4: Virtual environment and packages

This needs internet and takes a few minutes. Make sure there are at least 2 GB free on the disk.
Give the commands a 10-minute timeout.

```bash
"$PY" -m venv .venv
.venv/Scripts/python.exe -m pip install --disable-pip-version-check --upgrade pip
.venv/Scripts/python.exe -m pip install --disable-pip-version-check -r requirements.txt
```

If pip starts *building* a package from source, or says "no matching distribution", the Python is
the wrong version or 32-bit. Go back to Step 2.

## Step 5: Self-tests

```bash
.venv/Scripts/python.exe -m pytest -q tests
```

Expected result: **`120 passed`**, 0 failed. It takes about 6 s on the Mac, so expect well under a
minute on the laptop.

## Step 6: Install check (model reproduces + practice kit score)

```bash
.venv/Scripts/python.exe scripts/verify_install.py
```

Expected: both lines `PASS`, then `ALL CHECKS PASSED`, exit code 0.

- **[1/2] Reproduction.** On Windows the check may say *"within tolerance (not byte-identical)"*.
  That is still a pass. An Intel CPU can round a few last digits differently from the Mac's Apple
  CPU.
- **[2/2] Practice kit.** This line prints the accuracy on `judge_test/`. Copy the numbers into
  your report.

If a check fails, find the cause and fix it within the rules. Never regenerate or edit
`predictions.csv`.

## Step 7: Start the web app

Run it in the **background** (it keeps running), from the repo folder:

```bash
.venv/Scripts/python.exe app.py
```

It opens the browser at <http://127.0.0.1:7860> by itself. To confirm it is up:

```bash
curl --retry 30 --retry-delay 2 --retry-connrefused -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7860/
```

Expected output: `200`.

If port 7860 is busy, use another port:

```bash
.venv/Scripts/python.exe -c "import app; app.launch_app(7870)"
```

The user can also just double-click `run_app.bat`. To stop the app, stop that background task, or
close the `run_app.bat` window.

## Step 8: Tell the user the app is ready, then do Task 2

Send a short note:
- the Python version;
- the pytest result line;
- the two `verify_install.py` lines;
- the app URL (<http://127.0.0.1:7860>);
- anything you had to fix.

How to use the app:
- The language picker is at the top (English / हिन्दी / ಕನ್ನಡ).
- **Am I safe?** is the resident view.
- **Officer dashboard** has the map, the ranked rivers, the hydrograph, the why, the what-if and
  the CAP alert.
- **Batch** takes `test.csv` and returns `predictions.csv`, and gives a score if `answers.csv` is
  uploaded.
- **Manual input** predicts a single day.
- Without internet, the live forecast falls back to a saved forecast, and **Replay a past flood**
  works fully offline.

Then continue with Task 2.

## Task 2: fresh practice kit (Nov 2025 → Oct 2026), score, docs, push

`judge_test/` currently holds Jul 2024 → Jun 2025. For the 5 known rivers those dates are inside
the final model's training period (it ends 2025-10-31), so that score is optimistic. The new kit
uses 2025-11-01 → 2026-10-31, **after every training day**: a true unseen test, like the judges'.

### 2.1 Build it (needs internet)

```bash
.venv/Scripts/python.exe scripts/make_judge_kit.py
```

The script downloads USGS flow and Open-Meteo weather for 7 rivers. Station attributes come from
`data/processed/judge_kit_stations.csv`. Downloads are cached in `data/raw/judge/`, so a rerun
resumes.

Expected last line: `test.csv: ~2,550 rows, 7 stations, 2025-11-01 to 2026-10-31;
train_optional.csv: ~2,070 rows`. The exact counts depend on USGS data.

- **`Open-Meteo rate limit reached ... Daily API request limit exceeded`:**
  - The free daily limit resets at **00:00 UTC = 05:30 IST**. Networks sharing one public IP share
    the limit.
  - Tell the user, wait until after the reset, then rerun. Retry at most every 10 minutes; do not
    hammer the API.
  - The hourly limit resets on the hour.
- **USGS or Open-Meteo timeouts or 5xx errors:** rerun. Cached stations are skipped.
- **The script now raises `no rows for [...]`:** USGS has no data for that river. Report it to the
  user. Do not swap rivers yourself.

Then check that only the 4 kit files changed. Git may warn that CRLF will be replaced by LF in
`test_excel_messy.csv`; that is expected.

```bash
git status --short
```

### 2.2 Test and score

```bash
.venv/Scripts/python.exe -m pytest -q tests
.venv/Scripts/python.exe scripts/verify_install.py
.venv/Scripts/python.exe scripts/score_kit.py
```

- The tests and the install check must pass again, with **120 passed**.
- `score_kit.py` prints a markdown table:
  - two inputs: `test.csv` alone, and with `train_optional.csv`;
  - three river groups: all, known and new.

### 2.3 Update the docs

The app's "Practice files" note reads the kit dates by itself. Restart the app so it shows them.
Then edit three files.

**`README.md`, section `## Practice test kit (judge_test/)`:**

1. Replace the paragraph that starts "Files in the organizers' format" (it ends "West Fork San
   Jacinto, TX.") with:

   ```
   Files in the organizers' format, built by `scripts/make_judge_kit.py` from fresh USGS + Open-Meteo
   downloads for **2025-11-01 → 2026-10-31**, after every day the final model was trained on (its
   data ends 2025-10-31). They cover 5 rivers the model knows (Potomac, Mississippi at St. Louis,
   Colorado at Austin, Neuse, Rolling Fork) plus 2 it has **never seen**: French Broad at Asheville,
   NC, and West Fork San Jacinto near Conroe, TX.
   ```

2. In the table, change the `train_optional.csv` description to:
   `Earlier history (Jan 2023 → Oct 2025) for the two new rivers (optional)`.
3. Replace the paragraph that starts "Score on this kit:" (3 lines, ending "have no flow record.")
   with:
   - `Score of the shipped model on this kit (python scripts/score_kit.py):`
   - the table exactly as printed, with `R2` written as `R²`;
   - one or two sentences stating only what the table shows, for example which river group is
     weaker and whether `train_optional.csv` helps. No guesses about causes.

**`CONTEXT.md`, section 10 (Open items):** replace the last bullet (the fresh-kit one) with:
`- Practice kit rebuilt for 2025-11-01 → 2026-10-31 (after all training data) on <today's date>; scores in README.`

**`CONTEXT.md`, section 6:** add one line under "Practice kit" with the `all` row of `test.csv`
(RMSE, top-10% RMSE, MAE, R²).

## Judging: the organizers hand over a CSV

The judges run each team's model on their own `test.csv`, and the most accurate model wins. When the
user gives you their file:

```bash
.venv/Scripts/python.exe solution.py predict --test "PATH/TO/test.csv" --out "PATH/TO/predictions.csv"
```

If the judges also give a training/history file with past discharge, add `--train "PATH/TO/train.csv"`.
Its weather warms up the rainfall windows, and its discharge gives climatology for rivers the model
has never seen.

Output and validation:

- `predict` checks every rejection rule from the brief before writing: exact columns
  `station_id,date,discharge_cfs`, one row per test row, no NaN, no negatives.
- If it raises an error, show it to the user. Do not work around it.
- Excel quirks are handled automatically: dropped leading zeros, dd/mm/yyyy dates, soil moisture
  in %, semicolons, BOM, Windows-1252.
- If the judges also give the true values, upload `test.csv` + `answers.csv` in the app's **Batch**
  tab to see RMSE, top-10% RMSE, MAE and R².
- **Ask the user** before copying a judges' `predictions.csv` into the repo or pushing it.
- Double-clicking alternative for the user: drag `test.csv` onto `predict.bat`. It writes
  `predictions.csv` next to `test.csv`.

A 200,000-row file takes about 6 s and about 0.7 GB of RAM, so 8 GB is plenty.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `DLL load failed` / `vcomp140.dll` when importing lightgbm | Step 3 (C++ runtime), then rerun the tests |
| pip builds from source / "no matching distribution" | Wrong Python: must be 3.12 64-bit (Step 2). Delete `.venv`, then redo Step 4 with the right Python |
| "running scripts is disabled on this system" | PowerShell blocked `Activate.ps1`. Don't activate; call `.venv/Scripts/python.exe` directly |
| `pytest` command not found | Use `.venv/Scripts/python.exe -m pytest` |
| Port 7860 already in use | `.venv/Scripts/python.exe -c "import app; app.launch_app(7870)"` |
| pip install very slow | Windows Defender scans every file. Wait; don't cancel |
| Live forecast says offline / snapshot | No internet or Open-Meteo is down. Expected fallback; Replay works offline |
| `verify_install.py` reproduction FAIL (not just "within tolerance") | Check the install first: Python 3.12 64-bit, exact pins, a fresh `git status` with no edits under `models/`. If it still fails, report the printed numbers. Never regenerate `predictions.csv` |
| `make_judge_kit.py`: "Open-Meteo rate limit reached" | Wait for the reset (daily: 05:30 IST; hourly: on the hour), then rerun. Downloads resume |
| `git push` asks for a login / opens a browser | The user signs in to GitHub. `403` means no write access: tell the user |
| Files open in OneDrive / sync errors | Re-clone to `~/floodcast-midnight-cowens` (outside OneDrive) |
